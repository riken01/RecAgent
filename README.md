# 意图生成规则
综合所有轮次 query 与 response，识别用户对话背后的持续性需求，生成对应 Intent。

## Intent定义
Intent 表示：从连续对话中识别出的，用户在对话结束后仍可能持续关注、推进或需要帮助的阶段性目标或话题方向。
Intent 用于：话题推荐、功能推荐、主动服务。

核心判断：
**这段对话结束后，用户未来一段时间还可能关注什么？**

默认认为对话中提到的任务均已执行完成：
- 不重复推荐用户刚刚完成的任务
- 应基于当前对话推断用户后续可能感兴趣或需要帮助的方向

不生成：
- 一次性任务、即时查询/执行
- 仅获取当前问题答案的需求

生成：
- 可持续推进的目标
- 可产生推荐或服务价值的兴趣方向

可从以下方向预测：
1. 可扩展：当前目标未来可能延展的相关方向
2. 下一步意图：当前目标推进过程中可能产生的后续需求

## 规则
- Intent 不总结对话内容，而是提炼用户后续可能关注的目标。
- 若不存在持续性需求 → 不生成 Intent，输出空 add 数组。
- 若存在持续性需求 → 默认生成 1 个核心 Intent。
- 若存在明显不同领域的持续需求，可生成多个 Intent。
- 不根据最后一轮 query 单独生成，应结合完整对话判断。
- 手机设置、设备操作（如空调、音响、电视的遥控）类需求不生成 Intent。

### 特殊场景
**餐饮外卖意图识别**：用户在对话中表现出想吃、想喝、嘴馋等实际饮食需求，且目标食物适合外卖时，可生成餐饮外卖 Intent，采用「点XX外卖」的描述形式。
- 排除条件：仅讨论食谱、营养、美食知识，或明确计划到店体验（如米其林餐厅、高端料理）时，不生成

# searchQueries 生成规则

> searchQueries 仅为已确定的 ADD Intent 服务，不参与 Intent 发现或消解。

当下游 Chips 依赖实时或外部信息时生成，否则为 []。
- 默认 1 条，最多 2 条。
- Query 必须直接服务当前 Intent，只使用 diff 或 Intent 已有信息，不得创造新目标。
- 静态知识、教程、方法、经验无需搜索。

# memorySearchQuery 生成规则

用于检索与当前 Intent 相关的用户历史记忆。

- 内容：围绕该 Intent，生成一个适合检索用户历史记忆的查询语句。
- 查询重点是**用户自身相关信息**，如历史行为、偏好、经历、计划、进展、已有记录等。
- 不要查询通用知识，不要复述 Intent 本身。
- 应与 Intent 强相关，能够帮助后续服务更了解用户。
- 无明显相关的用户记忆时，仍生成简洁的主题查询。

# 注意事项

- name 固定为 ""submit_predicted_intents""。
- **Intent 是用户可能感兴趣的相关意图**：intentDesc 须站在用户视角描述其可能感兴趣的相关意图，不得描述助手/模型为完成任务而要执行的内部动作；也不得直接复制 query/response 原文或重复已完成的动作。
